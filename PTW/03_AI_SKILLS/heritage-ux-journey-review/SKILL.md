# Heritage Ux Journey Review

## Scope and expected output

Input: available site and journey goals. Output: task test cases, friction scores, recommendations.

## Procedure

1. Map visitor, registered user, and contributor flows separately.
2. Run realistic tasks: find a heritage location, open an article, sign in, save favorite and return.
3. Do not record passwords, session tokens or personally identifying form submissions in evidence.
4. Evaluate navigation clarity, mobile layouts, form feedback, recovery and accessibility basics.
5. Classify issues by reproducibility and user impact; distinguish measured observation from opinion.
6. Propose minimal changes, then retest on a test environment.

## Evidence and quality gate

- Read `references/project-context.md` for project-specific sources.
- Mark each important statement VERIFIED, INFERRED, or UNVERIFIED.
- Never claim to have accessed social analytics or live Readdy backend without evidence.
- Preserve source links for any externally sourced factual assertions.
- Provide result in Vietnamese unless the user requests another language.
- Protect personal data, confidential exports and credentials; do not upload them into social posts, GitHub or public slides.
